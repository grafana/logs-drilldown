## Frontmatter and site conventions

- Each page uses a `canonical` URL pointing at `https://grafana.com/docs/grafana/latest/explore/simplified-exploration/logs/...`, plus `description`, `keywords`, `menuTitle`, `title`, and `weight`.
- Weight / ordering rules: lower `weight` sorts first (for example landing `_index.md` = 100, `access/configure.md` = 200, `labels-and-fields/` = 600). Increment weights to control menu order.
- Internal link style: relative paths with a trailing slash, for example `../view-logs/` or `get-started/`.
- Markdown flavor is CommonMark rendered with Hugo; pages use Grafana Hugo shortcodes such as `{{< admonition >}}`, `{{< figure >}}`, `{{< card-grid >}}`, and `{{< docs/play >}}`.

## Conventions for agents

- **Query language / API naming** (exact terms): LogQL (Loki's query language). Use "labels", "fields", "patterns", and the special `detected_level` label (values: `debug`, `info`, `warn`, `error`, `fatal`, `critical`, `trace`, `unknown`). The product is queryless — emphasize that users don't need to write LogQL.
- **Storage or format version naming** (if any): not applicable; this is a frontend app plugin that queries Loki. Loki data source and its volume/pattern endpoints are the backend contract (Loki v3.2+ with `volume_enabled` and `discover_log_levels`).
- **Vale or linter config location** (if any): spellcheck via `cspell.config.json` and the `project-words.txt` dictionary (`yarn spellcheck`). Docs follow the Grafana [Writers' Toolkit](https://grafana.com/docs/writers-toolkit/) and Style Guide; build docs locally with `cd docs && make docs`.
